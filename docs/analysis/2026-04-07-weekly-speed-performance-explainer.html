What We Did (and Why)

Search path hardening
Skipped unnecessary expensive search behavior on low-value paths (short queries, heavy counts, costly metadata refreshes).
Why: improved first-result latency and reduced DB/search overhead during normal recruiter usage.
Mobile shell optimization
Moved heavyweight overlays/providers out of the global critical path and virtualized long mobile lists.
Why: faster shell hydration, less rendering pressure, and smoother list interaction on mobile devices.
Performance guardrails
Added route-level bundle budgets + hydration timing checks + mobile QA command path.
Why: avoid regressions by enforcing budgets and making slowness visible in telemetry/CI workflows.
